# Blog - agent notes

A static blog at <https://bogoyavlensky.com>, generated by a small Clojure app
(Rum for HTML, Tailwind CSS 1.x). Pages are built into `dist/`, and
`make deploy` publishes them to the `master` branch, which GitHub Pages
serves. Work happens on `dev`.

- Article list and metadata: `resources/data/meta.edn`.
  Article bodies: `resources/data/articles/<slug>.md`.
- Pages and meta tags: `src/blog/pages.clj`, `src/blog/app.clj`.
  Build: `src/blog/build.clj`. Social cards: `src/blog/og_card.clj`.
- Plans: `docs/plans/`.

## Commands

| | |
|---|---|
| `make test` | tests with coverage |
| `make lint` / `make fmt-check` | clj-kondo and cljstyle, run locally (CI runs them in Docker) |
| `make css-dev` | build CSS for the dev server |
| `make repl`, then `(reset)` | dev server on `http://localhost:8001` |
| `make clean && make build` | production build into `dist/`; needs npm and Docker |
| `make deploy '<message>'` | build and publish to the live site |

## Publishing an article

1. Add an entry to `:articles` in `resources/data/meta.edn`:
   - `:id` is the next number. The article list is sorted by `:id`, not by date.
   - `:slug` names the URL and the Markdown file.
   - `:date` is `YYYY-MM-DD`.
   - `:description` is required in practice. It becomes the meta description
     and the text under social previews, so never leave it empty.
   - `:keywords`: the first three also become `article:tag` meta tags.
2. Write the article in `resources/data/articles/<slug>.md`.
3. Put article images in `resources/public/images/articles/` as
   `<id>_<name>.png`, and link them as `/assets/images/articles/<file>`.
   Strip metadata from photos first, because phone photos carry GPS location.
4. The build generates a 1200×630 social card from the title. A title that
   does not fit in three lines fails the build: shorten it, or set `:og-image`
   to a 1200×630 file relative to `resources/public/images/`.
5. Run `make clean && make build`, then check the output:
   - `ls dist/assets/images/og/` has a card for the new slug.
   - `grep -lE 'load build definition|npm WARN' -r dist --include=*.html`
     prints nothing. Article HTML comes from `docker compose run marked`. On a
     machine where that image is not built yet, the first article rendered
     gets Docker's build log instead of its content, and the build still
     passes. Rebuilding fixes it.
6. Commit on `dev`.

## Deploying

`make deploy` checks out `master`, commits the build, pushes it to the live
site, and switches back to `dev`. Run it only when the author asks, and only
from `dev` with a clean tree. Never push `master` by hand.

After a deploy that changes previews, re-scrape shared links in the Facebook
Sharing Debugger and LinkedIn Post Inspector, because platforms cache them.

## Conventions

- CSS classes are purged: Tailwind scans `src/**/*.clj`, so write every class
  as a complete string literal, never built by concatenation.
- Fonts are self-hosted: Inter and JetBrains Mono WOFF2 files in
  `resources/public/fonts/`, and TTF copies in `resources/fonts/` that only
  the card renderer uses.
- The CI image has no font libraries. Code that draws text must not run while
  a namespace loads, and render tests skip themselves when fonts are
  unavailable.
